# Audit improvements – manual steps

**Do not run database changes automatically.** Apply SQL in Supabase SQL Editor.

## 1. Unifying contest manual close

- **DB:** `close_contest` now has `SET search_path TO 'public'` (in migration SQL below). No other DB change.
- **Edge function:** `close-contest` was updated to call `close_contest` RPC instead of “highest ticket wins”. Manual close now uses **random draw** among sold tickets (single source of truth). Deploy the updated `supabase/functions/close-contest/index.ts` when ready.

## 2. Hardening wallet updates

- **DB:** New function `deduct_wallet_for_refund` does atomic `GREATEST(0, balance_coins - p_amount)`. Migration adds it and the `wallets_balance_coins_non_negative` CHECK (NOT VALID).
- **Edge function:** `stripe-refund` was updated to call `deduct_wallet_for_refund` RPC instead of read-then-write. Deploy the updated `supabase/functions/stripe-refund/index.ts` **after** applying the migration (so the RPC exists).

## 3. Apply SQL first

Run the contents of `20260315140000_audit_improvements_close_wallet.sql` in Supabase SQL Editor. Then (optional) fix any negative balances and run:

```sql
ALTER TABLE public.wallets VALIDATE CONSTRAINT wallets_balance_coins_non_negative;
```
